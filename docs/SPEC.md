# Техническое задание — облачный финансовый трекер

**Версия:** 0.2.0  
**Статус:** стартовый код для MVP; требуется настройка внешних сервисов и тестирование перед публичным запуском.

## 1. Назначение
Адаптивное веб-приложение для учёта личных финансов. Доступно по публичной ссылке, поддерживает публичную регистрацию и синхронизацию данных пользователя между устройствами через облачную базу.

## 2. Роли
- **Гость:** может открыть сайт, зарегистрироваться или войти; не имеет доступа к финансовым записям.
- **Пользователь:** управляет только собственными операциями и лимитами.
- **Администратор инфраструктуры:** управляет настройками хостинга/БД, не является пользовательской ролью приложения. Админ-панель в MVP не входит.

## 3. Функциональные требования
1. Регистрация по email и паролю.
2. Вход и выход, сохранение сессии.
3. Добавление доходов и расходов с суммой, категорией, датой и необязательным описанием.
4. Месячная сводка доходов, расходов, баланса и лимитов.
5. Настройка лимита для категории на конкретный месяц.
6. Визуальное предупреждение на 80% лимита и при превышении 100%.
7. Аналитика по категориям доходов и расходов.
8. История операций с фильтром по типу и удалением.
9. Экспорт операций выбранного месяца в CSV.
10. Доступ к одним и тем же данным после входа с другого устройства.
11. Изоляция данных между аккаунтами с помощью PostgreSQL Row Level Security (RLS).

## 4. Нефункциональные требования
- Адаптивность от 320 px до широких экранов.
- HTTPS на публичном хостинге.
- Проверка данных на клиенте и ограничениями БД.
- Ни один секретный service-role ключ не попадает во frontend.
- Ошибки регистрации, входа и сохранения отображаются пользователю.
- Поддержка актуальных Chrome, Edge, Firefox, Safari.
- Не использовать финансовые данные для рекламы и не отправлять их в аналитические системы без отдельного решения и согласия.

## 5. Границы MVP
Не входят: банковские интеграции, автоматический импорт выписок, мультивалютность, совместные кошельки, восстановление пароля в UI, 2FA, push-уведомления, админ-панель, подписки/платежи. Восстановление пароля рекомендуется добавить до публичного релиза.

## 6. Критерии приёмки
- Пользователь может зарегистрироваться и войти.
- Данные операции после перезагрузки доступны тому же аккаунту.
- Тот же аккаунт видит те же данные на другом устройстве.
- Пользователь A не может читать, создавать, изменять или удалять строки пользователя B.
- Невалидные суммы отклоняются интерфейсом и БД.
- Лимиты уникальны по пользователю, категории и месяцу.
- CSV корректно скачивается.
- Приложение собирается командой `npm run build`.
- Публичный сайт доступен по HTTPS после настройки хостинга.
